# Architecture Decision Records

Short records of decisions that are easy to accidentally undo while making an
unrelated change. Each ADR is deliberately small. If a future change conflicts with one
of these, either the change is wrong or the ADR is outdated — update the ADR
explicitly rather than silently drifting away from it.

See `docs/SYSTEM_ARCHITECTURE.md` for the full current-implementation context these
decisions live in, and `docs/DOMAIN_GLOSSARY.md` for term definitions.

| [0012](0012-training-plans-domain-and-execution-model.md) | Training Plans use lazy Block creation and a session-snapshot execution state (never a live plan reference); plan/step types live centrally in `src/types/index.ts` to avoid a domain-type cycle; `Session.planExecution` migration discards-not-repairs like Assessment; progression is always keyed by stored `blockId`, never array position |
| [0013](0013-application-owned-persistence-repository-boundary.md) | **Accepted. Implemented.** Domain-facing, application-owned repository boundaries (one per persisted domain) wrap the existing `localStorage` implementation unchanged, in preparation for a later IndexedDB adapter and a future sync layer above local persistence — see `docs/PERSISTENCE_BOUNDARY_DESIGN.md` |
| [0014](0014-session-archive-write-ordering.md) | **Accepted. | [0015](0015-indexeddb-adapter-unwired.md) | **Accepted. Implemented (adapter only — not activated).** A second `StorageAdapter` implementation, backed by `idb` over a two-store (`records`/`metadata`) IndexedDB database, exists and is tested — `localStorage` remains the sole production source of truth; no migration, activation, or dual-write is implemented |
| [0016](0016-resumable-localstorage-to-indexeddb-copy-migration.md) | **Accepted. Implemented (mechanism only — not invoked).** A resumable, per-domain copy migration (`localStorageToIndexedDbMigration.ts`) copies exact serialized strings from `localStorage` into IndexedDB behind deterministic, fail-closed per-domain markers in the `metadata` store — no domain-schema re-migration, no app wiring, no activation |
| [0017](0017-indexeddb-activation-verification-and-rollback-protocol.md) | **Proposed. Incomplete design — automatic production activation blocked pending one bundled, separate decision (Decision 3: old-build/deployment fencing, plus the row-0b fault-model gap below — not two independent prerequisites).** Per-domain authority computed from two independent, fingerprint-bound activation-evidence records (a new per-domain `localStorage` witness plus a new IndexedDB `metadata` record, distinct from ADR-0016's migration marker) — authority begins only once evidence reaches `committed` and matches the witness, never at the earlier `prepared` step; an interrupted `prepared`+witness state recovers automatically and crash-resumably by deleting the witness before the evidence (the reverse of manual rollback's order, deliberately); an authority-aware mutation lease (per-domain Web Locks, held for the whole verify-through-finalize sequence, one lease and exactly one durable-evidence check per complete logical mutation — immediately before its first write, never repeated before a later write in the same mutation) rather than a lock around each individual write; a bounded (≤2-pass) verification sequence; a regenerated truth/crash table including a named, bounded gap when a witness is lost while IndexedDB is simultaneously unreachable; and rollback reclassified as manual/blocked/deferred (never automatic) — `localStorage` remains authoritative and IndexedDB remains unactivated |
| [0018](0018-indexeddb-production-activation-fencing-and-outage-policy.md) | **Proposed. Incomplete design.** The attempted answer to ADR-0017 Decision 3's bundled prerequisite — resolves **neither** half. Decision 13 row 0b is narrowed, not closed: a proposed `localStorage` Activation Ledger, corrected to be established as a barrier *before* IndexedDB evidence finalizes (never as a best-effort write after), catches an ordinary witness loss while IndexedDB is unreachable. It is **not self-healing**. A targeted ledger deletion (making the ledger absent) does not by itself recreate row 0b while the witness remains present — it only removes this domain's future mitigation against a *later*, independent witness loss coincident with IndexedDB being unreachable; a whole-`localStorage`-origin wipe removes ledger and witness together in one action, directly recreating the original ambiguity the moment IndexedDB is unreachable. Ledger corruption is different again: an invalid or unreadable ledger fails closed (`invalid_activation_metadata` / `activation_ledger_unreadable`) and never silently selects `localStorage` — it costs availability, not safety. Row 0b stays bundled into ADR-0017 Decision 3 pending an explicit residual-risk decision — accepting that residual would resolve the pending governance decision, not technically eliminate the ambiguity itself; only unconditional fail-closed behavior would do that. Old-build/tab exclusion is **not resolved** either — a Web-Locks presence check, corrected to a single acquisition per tab (querying every historical lock-name version, fail-closed on any request/query failure, never a "safe no-op" when Web Locks is unavailable) plus an explicit, honest, unverifiable user confirmation (scoped to this browser's own storage partition, not other devices) is the best achievable design without a backend, and this ADR proves directly why no candidate (staged deployment, service worker, handshake, broadcast, Web Locks alone, a bare session registry, or the presence-check-plus-confirmation itself) can make already-running old JavaScript stop writing — a redesigned server-authoritative backend could make such writes non-authoritative, never prevent the local `localStorage.setItem` call itself. ADR-0017 Decision 3 therefore remains blocked as a whole; no activation is recommended |
| [0019](0019-cloud-identity-and-data-authority-transition.md) | **Proposed. Incomplete design — genuine architecture blockers remain, not merely missing implementation.** Three independent state machines — `LocalGenerationState`, `AccountDomainAuthority`, `SessionAccessibility` — stay separate. The **`RemoteAuthorityBarrier`** is established under the same exclusive, domain-scoped mutation lock adoption itself uses. Drift a barrier's resolution detects is now recorded in a **new, permanent artifact, `RemoteAuthorityDriftEvidence`** — the prior "one-directional drift" claim had no durable memory across a reload, so bytes reverting to the original baseline could silently, incorrectly re-report `remote_authority_quarantined`; the new evidence, once written, makes `local_branch_quarantined` unconditional regardless of what the bytes currently look like. Fingerprinting is split into **`captureDomainSnapshot`** (I/O) and **`fingerprintDomainSnapshot`** (a pure function over an explicit snapshot), replacing an ambiguous `fp1(domain)` that different sections used to mean different operations; a canonical empty-domain fingerprint is defined explicitly. **The `cloud_authoritative` case remains a total switch over every `LocalGenerationState` value**, with explicit treatment for `legacy_quarantined` (this device's own committed fence is reused regardless of which account it recorded — a committed fence is restated to prove local-generation quarantine only, never which account currently holds cloud authority, and the signed-in account is never required to match it). `adoption_prepared` recovery is restructured from five overlapping local-evidence-first cases into an **ordered, server-state-first decision tree** (branches A/B/C, keyed by whether the server reports `adoption_prepared`, `cloud_authoritative`, or this specific run `aborted`) — the prior structure let its own compatibility table describe a fence-present row as eligible for a case that explicitly required no fence, a direct contradiction. Two new named blocking results, **`missing_prepared_claim_evidence`** and **`missing_abort_claim_evidence`**, cover a prepared fence whose Claim Marker is anomalously absent. **Committed-fence catch-up is now its own 11-step exclusive recovery protocol** (re-acquiring the lock, re-validating the registry, converging two concurrent attempts on one committed fence), since a crash releases the original lock and catch-up cannot resume without reacquiring it. The `AbortCleanupCursor`'s recovery is now an **exact four-checkpoint matrix**, replacing a broad "operationally irrelevant" claim — a malformed or mismatched marker or archive at any checkpoint fails cleanup closed. The account-domain authority registry's discriminated-union bootstrap model gains an explicit **`authorityRevision: "0"`** starting value and a **future-domain backfill migration** requirement for domains introduced after accounts already exist. `not_initialized` is corrected to mean only a present, persisted row, never a missing one. **A narrow final pass then corrected four more defects**: a prepared fence's Claim Marker is now deliberately left unread by the local resolver until the server's own state for that run is known (validating it earlier made committed-fence catch-up's "marker unreachable" rule unreachable in practice); drift evidence now preserves the exact fingerprint that first proved drift occurred, never a later in-lock re-capture a non-participating build could have already reverted; committed-fence catch-up's concurrent-attempt convergence now fully validates a found committed fence's schema, bindings, and archive before accepting it, never status/runId alone; and a stale enum comment describing "any fixed-key artifact, including any Claim Marker" as unconditionally fail-closed is corrected to state the marker's fail-closed behavior is conditional on reachability. Production cloud authority for any domain remains disabled while ADR-0019 itself is Proposed. Requires a follow-up ADR-0020 for concrete schema/RLS/the account-domain authority registry |
| [0020](0020-supabase-schema-rls-and-adoption-transactions.md) | **Proposed. | [0021](0021-assessment-draft-history-authority-unit-split.md) | **Accepted. Design complete — implementation not yet performed.** Splits the combined Assessment persistence domain into `assessmentDraft` (permanently device-local; owns the current run, including a terminal run retained until its exact history insertion is durably confirmed and the draft is safely cleared — that terminal run is never itself cloud-eligible) and `assessmentHistory` (owns terminal runs once durably archived, the only Assessment unit ever eligible for future cloud adoption), resolving ADR-0020 Decision D's authority-unit blocker in full (never again "blocked by Decision D"). One evidence-backed, crash-resumable establishment protocol covers both fresh initialization and legacy migration (distinct origins, distinct evidence variants — never conflating malformed/absent legacy data with "nothing to migrate"), including a mandatory automatic restart for a drifted in-progress migration and an executable supersession path when legacy data appears mid-fresh-initialization; one unified, non-reentrant Web-Locks mutation runner, shared by every Assessment writer (public repository methods call it directly; the archive coordinator enters it exactly once and uses only context-bound internal operations, eliminating any re-entrant-lock deadlock), re-checks durable authority exactly once, immediately before each logical mutation's first write — never repeated before a later write in the same mutation — a technical elimination of current-build-vs-current-build races, not a residual risk anyone had to accept; the old-build hazard is documented and deterministically classified (`legacy_branch_detected`/`legacy_residue_missing`: preserved, never merged, writes refused pending reconciliation, with reads still available under an explicit, non-boolean write-disposition value) but production execution of the establishment protocol remains a separate, not-yet-made deployment-fencing decision; post-commit target validity is ordinary schema/domain/pair validation, never a perpetual fingerprint check against mutable data; run-to-run equality throughout uses exact canonical serialized comparison, never a hash; the archive-and-clear mutation derives its source run from the repository itself under the lease, requires an explicit `expectedRunId` so a retry after full success converges to success, and rejects (never silently resolves) a same-ID-different-content conflict; `localStorage` remains sole production authority and no runtime code changes |
